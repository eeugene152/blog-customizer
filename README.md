### Функциональные требования

- При нажатии на «стрелку» открывается сайдбар с настройками, при повторном нажатии или клике вне сайдбар закрывается.
- При изменении настроек в сайдбаре они не применяются сразу.
- После нажатия на «применить» стили применяются к статье.
- При нажатии «сбросить» настройки в форме сбрасываются на начальные, которые были при открытии страницы, и стили применяются к статье.
- Настройки устанавливаются через CSS-переменные, которые уже есть в стилях и установлены в коде в дефолтные значения.

### Задача проекта
Оживить панель кастомизации страницы блога: реализовать плавное открытие и закрытие бокового меню настроек, сборку формы из готовых UI-компонентов и управление внешним видом статьи (шрифт, размер, цвета текста и фона, ширина контента) через CSS-переменные. Главная логика: изменения в форме не должны применяться к статье мгновенно — страница обновляется только по кнопке «Применить» или возвращается к исходному виду по кнопке «Сбросить».

### Что было сделано
* **Управление стилями статьи (`App`):** перевел корневой компонент со статичных констант на реактивное состояние (`useState`), значения которого напрямую передаются в CSS-переменные тега `<main>`.
* **Сборка и верстка формы (`ArticleParamsForm`):** собрал панель настроек по макету из компонентов UI-кита (`Text`, `Select`, `RadioGroup`, `Separator`, `Button`) и настроил сетку отступов.
* **Открытие и закрытие сайдбара:** реализовал переключение видимости панели по клику на кнопку-стрелку с помощью условных классов `clsx`, а также автоматическое закрытие при клике за пределами панели.
* **Изоляция состояний и обработка формы:** разделил состояние самой страницы и локальный «черновик» внутри формы. Привязал отправку (`onSubmit`) и сброс (`onReset`) к событиям тега `<form>`, чтобы страница обновлялась только после подтверждения пользователем.
* **Рефакторинг по итогам ревью:** вынес кастомный хук закрытия по клику в оверлей в общую директорию `src/hooks`, заменил повторяющиеся обработчики полей на единую функцию-фабрику и привел все импорты к единому стилю через алиасы `@/`.

### Использованные техники и инструменты
* **React и хуки:** функциональные компоненты, управление состоянием (`useState`), работа с DOM-ссылками (`useRef`), подписка и очистка глобальных событий браузера (`useEffect`), переиспользование логики через кастомный хук (готовый) (`useOutsideClickClose`).
* **Архитектурные паттерны:** «подъём состояния» (Lifting State Up) от дочерней формы к родительскому `App` через колбэк-пропсы, управляемые элементы форм, предотвращение стандартного поведения браузера (`preventDefault`).
* **TypeScript:** типизация пропсов и состояний (`ArticleStateType`), типизация DOM-событий (`MouseEvent`, `FormEvent`), использование `keyof` для создания типобезопасного обработчика-фабрики.
* **Стили и качество кода:** динамическая передача CSS-переменных через `CSSProperties`, условная композиция классов через `clsx`, настройка путей через алиасы (`@/`), проверка кода линтерами ESLint и Stylelint.

### Сложности, которые удалось преодолеть
* **Ловушка всплытия событий при закрытии панели:** изначально слушатель `click` на документе срабатывал в тот же момент, когда пользователь кликал по стрелке для открытия меню, и сразу закрывал его. Решил проблему переходом на событие `mousedown` и размещением общего `ref`-контейнера вокруг кнопки-стрелки и панели `<aside>`.
* **Избавление от дублирования кода (DRY):** вместо пяти однотипных инлайн-функций `onChange` для каждого поля формы написал универсальный обработчик-фабрику, который принимает ключ из `ArticleStateType` и возвращает готовую функцию обновления нужного свойства.
* **Чистота зависимостей между компонентами:** чтобы форма не зависела от внутренних файлов компонента `Select`, вынес общий хук `useOutsideClickClose` в корневую папку `src/hooks` и обновил импорты в обоих компонентах.
